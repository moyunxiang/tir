Smoke tests: post-tool entropy in tool-integrated reasoning (pre-registration)

Written 2026-11-04, before any rollout from a trained checkpoint existed (engine tests used an unrelated 0.5B chat model). Sample sizes in §1 may be reduced after the throughput pilot; hypotheses, metrics, tests and decision rules may not change after that. Any later change is listed in report_*.md under "Deviations".

Question. Is high token entropy right after a tool result useful exploration, or unstable continuation? How do the content and form of tool feedback change that?

Status of the results. A smoke test on a laptop: at most about 20 problems, one model family. It can find large effects and rule out a broken design. It cannot establish small effects, and a null means "not detected at this size".

2. Problem selection (fixed before seeing calibration results)

From calibration, keep problems with at least one root that made a tool call and continued. Take up to 70% from mixed-outcome problems (0 < success < 1 over the four roots), then alternate all-correct and all-wrong problems. All draws are seeded. This does not condition on any entropy value. Regression to the mean on success is possible and is why roots are never compared with their own continuations as an effect estimate.

3. Experiment A: entropy vs continuation quality

States. Post-tool states: context up to and including the tool result. Placebo states: a random position in ordinary reasoning text of the same problem's roots, not inside code and not right after a tool result. Without the placebo a correlation could not be attributed to tools.

Entropy predictors.

  • H_first: entropy of the first token after the state. Exact, not sampled, and fixed before any continuation is drawn. The only predictor that cannot be affected by the continuation's outcome.
  • H10 (primary), H50: mean token entropy over the first 10 / 50 generated tokens, averaged across continuations. These depend on the sampled path, so an association with outcome can be a consequence of the path rather than a cause.

Outcomes per state.

  • success: fraction of continuations with the correct boxed answer.
  • valid: fraction ending in a boxed answer, with no void turn, no truncation, no turn-limit stop.
  • void: fraction ending in a void turn (SimpleTIR definition: neither a complete code block nor \boxed). void_eos and void_trunc are reported separately.
  • code_err: fraction with at least one later tool error.
  • pass@k for k=1,2,4,8: exact hypergeometric chance that k draws without replacement from the C continuations include a correct one.
  • answer_div: exp(Shannon entropy) of the answer distribution among valid continuations.
  • strategy_div: exp(Shannon entropy) of a code signature among valid continuations. Signature = sorted set of imported modules, called function names, and control keywords (for, while, if) in the first code block after the state; no code = its own class. A proxy for strategy, not a judgement of it.
  • outcome_unc: binary entropy of success, i.e. how much the branch outcome depends on the sample (APPO's notion).

Tests. State-level, within-problem Spearman (values demeaned within problem), p by 10,000 within-problem permutations, 95% CI by problem-cluster bootstrap, Benjamini–Hochberg across the primary family (H10 × {success, valid, void, answer_div, strategy_div, outcome_unc}). Same for the placebo states, and the post-tool minus placebo difference with a cluster-bootstrap CI.

Taxonomy (descriptive). Among states in the top entropy tercile (H10, within the whole sample): productive = valid ≥ 0.75, success > 0, and answer_div or strategy_div ≥ 1.5; degenerate = valid < 0.75; lexical = valid ≥ 0.75, answer_div < 1.5, strategy_div < 1.5; misled = valid ≥ 0.75, success = 0, diverse. Thresholds fixed here.

Reading.

  • Evidence for "entropy marks useful exploration": H10 positively related to pass@8 or diversity, without a drop in valid.
  • Evidence for "entropy marks instability": H10 negatively related to valid / positively to void.
  • Both can hold at once; the taxonomy is what separates them.
  • A correlation only counts as tool-specific if the CI of the post-tool minus placebo difference excludes 0.

4. Experiment B: tool feedback intervention (the causal arm)

Prefix. One per problem: the first root whose first code turn ran with non-empty stdout of at most 200 characters containing a digit and no \boxed. Selected on the tool result only, never on the outcome. Same prefix across all conditions, same seed list.

Conditions.

Condition Text after the code block What changes relative to normal
normal real stdout in the official format reference
perturbed digits changed, same format and length, gold value excluded content only (wrong value)
irrelevant stdout of a different problem's prefix content only (unrelated)
error ZeroDivisionError: division by zero in the official format execution failed, no information
verbose same stdout wrapped in sandbox log lines, under the 512-char limit length and structure, same information
text_only \nThis gives: {stdout}\n form only (not marked as a tool result)
empty \nCode execution result: \n no information; real output for code that prints nothing

error_name and timeout are measured at the first token only (no sampling).

Outcomes. H_first and JS divergence from normal at the first token (both exact), H10, H50, valid, void, success, code_err, extra tool calls, plus: adopt (final answer contains a number from the injected payload) and retry (model calls a tool again).

Tests. Paired by prefix: each condition minus normal. Wilcoxon signed-rank, Holm across the six conditions within each outcome; 95% CI by bootstrap over prefixes. A condition's effect is called detected only when Holm-adjusted p < 0.05 and the CI excludes 0.

Key contrast. Dissociation: two conditions with similar H10 (|difference| < 0.1 nats) but valid or success differing by more than 0.2 with a CI excluding 0; or a condition that raises entropy without lowering quality alongside one that raises it and lowers quality. Either would show entropy does not by itself determine continuation quality. The absence of any dissociation would count against the idea.

Length confound. verbose changes length by design, and the other conditions differ by a few tokens. Observation length is reported per condition. perturbed and irrelevant are the clean content contrasts; text_only is the clean form contrast.

5. Experiments C and D

C: branching at inference time. For each problem, every arm starts from the same two roots (the first two calibration rollouts) and has the same budget: tokens = 3 × mean root tokens (clamped to 600–3000), tool calls = 3 × mean root calls (at least 3). Arms choose where to resample: random token, tool_boundary (first token after a tool result), high_entropy (highest entropy over all policy tokens), low_entropy (lowest), and posttool_high (highest within 50 tokens after a tool result, closest to ARPO). A minimum spacing of 8 tokens avoids spending the budget on adjacent positions. A branch that crosses the budget is cut off and counts as spent.

Primary: pass@budget (any leaf correct, including the roots), on all problems and on the rescue subset where both roots failed. Secondary: valid rate of branches, distinct valid answers, correct branches per 1,000 tokens. Each arm versus random, paired by problem, exact sign test; with 15 problems only a large effect could be detected, so results are descriptive unless the test passes.

D: void-turn audit, no new generation. All rollouts from calibration, A, B and C. Per turn following a tool result: void hazard by tercile of H_first; H_first and H10 for void versus non-void continuations from the same state (paired, removes state effects); trajectory classes (correct / wrong answer / void_eos / void_trunc / turn limit) compared by entropy, surprisal and the per-token logit-gradient proxy. The proxy is sqrt(1 − 2p_a + Σp²); it measures sensitivity of log p(a) to logits. No training gradient is computed, so no statement about gradient explosion can follow from D. With fewer than 20 void events, D is descriptive only. Void events caused by the laptop token limit (void_trunc) are reported separately so a limit artefact is not mistaken for a model failure.

6. Gates and fidelity

  • Sandbox self-test (sandbox.py) and engine test (test_engine.py) must pass.
  • Protocol gate (after pilot): at least half the rollouts call the tool, and tool results are visibly used. If not, stop and inspect the format before spending the night.
  • Fidelity: 4-bit versus published fp16 weights on real rollouts, by position. Report Spearman and mean |ΔH|. If Spearman < 0.9, all entropy results are labelled as properties of the quantised model only.
  • Novelty. notes/smoke_novelty.md lists overlap with APPO, AEPO, ProCredit, TAO-RL and tool-trust papers.

7. Deviations made after the pilot and before any main-run data

The pilot (5 problems × 4 roots, runs/simpletir7b/pilot.jsonl) is used for protocol checks only and is excluded from every analysis.

  1. Token limits raised from 1024 per turn / 2500 per rollout to 2048 / 4096 for roots (2500 new tokens for continuations). In the pilot 5 of 20 rollouts ended as void_trunc and 4 as budget. Their tails were ordinary reasoning or code cut mid-line with no repetition, so the 1024 limit was creating false void turns.
  2. Sizes reduced as allowed above: measured throughput is about 40 tokens/s, and rollouts are longer than assumed (mean 1195 tokens under the old limits).
  3. Fidelity reference is 8-bit, not fp16: the machine already had 19 GB of swap in use and fp16 needs about 14 GB. So §6 measures sensitivity to quantisation level, not distance from the published weights.

Hypotheses, metrics, tests and decision rules are unchanged.

8. Causal language

Only B randomises anything about the tool result, and only with respect to the injected text. A, C and D are observational or conditional on sampled paths. Reports must keep "observed", "hypothesis" and "unverified explanation" apart.
