High entropy after tool feedback: report on four smoke tests

2026-11-06. All numbers come from experiments/smoke/results/simpletir7b/; raw trajectories are in experiments/smoke/runs/simpletir7b/ (not in git). Pre-registration: PREREG.md, commit ca8d6c8, committed before any real rollout.

This is a smoke test on a laptop: one model, 4-bit quantisation, at most 36 problems. It can find large effects and design errors. It cannot establish small effects. "Not detected" means only that nothing was detected at this size.

1. Conclusions

Observed results

  1. Entropy and continuation quality can move separately (B, intervention, 15 prefixes). Changing only the form raises H10 with no detected change in quality: verbose H10 +0.250 (Holm .027), success +0.033 (Holm .747); text_only H10 +0.162 (Holm .002), success −0.033 (Holm .747). Changing only the digits lowers success, while the rise in H10 is not detected: perturbed success −0.333 (Holm .030), valid −0.256 (Holm .031), H10 +0.099 (Holm .096).
  2. The pre-registered dissociation criterion is met. For example, perturbed versus text_only: H10 differs by only 0.063 while success differs by 0.300 (95% CI −0.433 to −0.167). Six of 42 comparisons meet the criterion (no multiple-comparison correction).
  3. High-H10 states have lower mean quality, but this does not pass the pre-registered correction (A). Within-problem Spearman of H10 with success is ρ=−0.446 (permutation p=.045, BH .262). No pre-registered primary correlation passes BH. H10 depends on the sampled path, so it cannot be read causally; H_first, which does not, shows no such relation with success (ρ=+0.166, p=.562). Nor is there evidence that the relation is specific to tools: the interaction with placebo has a CI that includes 0.
  4. Void turns are almost one fixed string (D). Of 216 void_eos rollouts, 199 (92.1%) have a last turn that is exactly Reach max function call limit., and 193 of those occur after 4 tool calls. Among continuations of the same state, no difference in H10 between void and non-void is detected (difference −0.047, CI −0.125 to 0.020, n=75 states).
  5. This string is triggered jointly by the protocol's final-turn \n and a non-empty tool result (post-hoc probe, first token only). After 4 calls, P(Reach) is 0.0007 without the suffix, 0.4042 with it (CI 0.278–0.512), and 0.0037 with the suffix and a blanked tool result.
  6. Choosing branch points by entropy at inference time shows no advantage (C, 10 problems). No arm significantly beats random. tool_boundary has the highest point estimate (branch accuracy .572 versus random .300; sign test 5 wins, 1 loss, p=.219). high_entropy .260, posttool_high .262.
  7. H_first is sensitive to quantisation. 4-bit versus 8-bit at the first token after a tool result: Spearman only .643 (n=18), mean abs(ΔH) .221; a replay control with the same 4-bit model gives .998 and .009. Across all tokens Spearman is .965, above the pre-registered 0.9; but the self-control is only .975, because this measure is affected by the many entropy values near 0, so abs(ΔH) should be read alongside it.

Hypotheses (not verified)

  • High entropy mixes at least two sources: uncertainty from the form of the feedback, and uncertainty from content that conflicts with the context. The former does not hurt quality here.
  • Methods that reward or branch on entropy may reward format changes unrelated to content. Only inference-time continuation was measured here; there was no training.
  • The model saw this final-turn format and limit string during training and learned the reaction. The source of the string is currently unknown: it was not found in the public SimpleTIR code or the papers checked.

Explanations not yet verified

  • No training gradient was computed. gn is only a proxy for the sensitivity of log p(a) to logits, and its maximum is about 1.27–1.39 across all trajectory classes. These results neither support nor rule out gradient explosion.
  • Why tool_boundary has the highest point estimate is unknown. Its branch positions differ from the other arms (§3.4), and n=10.
  • The mechanism by which perturbed lowers quality is not established. The case study shows the model adopting a wrong number directly (§4), but the difference in adopt is not detected (−0.278, Holm .151).

4. Case studies

Cases are chosen by a rule in analyze.py (case_studies.md), not picked by hand.

Success and failure from one prefix (B, math_counting_and_probability_25149, 1.00 to 0.00, the largest drop). The answer is 63.

  • normal (Code execution result: 63, H_first .141): ...is \(\boxed{63}\). This result has been verified through the code and is accurate. Correct.
  • perturbed (Code execution result: 39, H_first .035): ...is \(\boxed{39}\). This result has been verified through the code and is accurate. Wrong. First-token entropy is low, and the model still adopts the wrong number.
  • error (H_first .002): It seems that there was an error due to incorrect range values..., rewrites the loop, correct.
  • verbose (H_first 1.304): The number of integer coordinate points ... is \(\boxed{63}\). Highest first-token entropy, still correct.

High entropy and valid (A, aime24_10:r1:t3, H10 1.71, success .83, valid .83). One continuation gives \boxed{371}, correct; another keeps rechecking until the turn limit (Interestingly, it yielded ...).

High entropy and degenerate (A, aime24_10:r3:t3, H10 2.04, success 0, valid 0). Openings include It appears that my code might be flawed... and It appears our logic still isn't correct.... All 6 continuations first write code and get a result; in the next turn (after 4 calls) 5 of them output Reach max function call limit., which counts as void, and the other reaches the turn limit. In 2 of them the tool output already contains this problem's correct answer (for example Sum m + n: 371), yet this string means no answer is given. So the low quality of this high-entropy state comes at least partly from the fixed final-turn output (an observation about this one state).

Fixed void (calibration, calib:aime24_01:0, turn 5, after 4 calls). The previous tool result is None. The first token of the next turn is Reach, with probability about .987 (logp −0.013) and H_first .073, followed by the whole string and EOS. In this example the void is low-entropy; it does not look like a collapse after uncertainty.

5. Key Findings / Minimal Interpretation

Label: Interpretation, not a first-level conclusion.

Answer to the core question: for this model and at this size, high entropy after tool feedback does not by itself indicate either valuable exploration or unstable continuation. Content (whether the numbers are right) can lower quality while the change in H10 goes undetected; form (logs, no tool marker) can raise H10 with no detected change in quality. In A, high-H10 states have lower quality, but this does not pass correction and may come from path dependence.

D also suggests caution in using void as a proxy for "instability": in this model, void is mainly a fixed output sensitive to the protocol's format.

Relation to existing methods (Interpretation): ReTool excludes tool-output tokens from the policy loss, but the tool output stays in the context, and B measures the effect of that content on later tokens; SimpleTIR filters void trajectories, while void here is mostly a fixed string; ARPO uses the rise in post-tool entropy as a branching signal, and the rise is replicated here (§3.5), but equal-budget branching shows no advantage for choosing positions by entropy (§3.4, n=10).

6. Limitations

  • One model, 4-bit. Post-tool first-token entropy is sensitive to quantisation (§3.6), so H_first results should be taken as properties of the 4-bit model only. Fidelity of H10: not computed. fp16 was not compared. The ARPO model replication was not run.
  • Small size. B has 15 prefixes, A 30 states, C 10 problems. Not detected does not mean no effect: the success point estimates for irrelevant and empty fall by .178 and .167.
  • Multiple comparisons. Holm is applied only within an outcome. The 42 dissociation comparisons are uncorrected. The 0.1 threshold is pre-registered, but two results sit right on it.
  • H10 is path-dependent. B intervenes on the feedback, not on entropy, so entropy cannot be said to cause any outcome; only the effect from feedback to outcome is a causal estimate.
  • Length. verbose differs in length (133.7 versus 30.7 tokens). text_only also changes a little text besides the tool marker. B's budget rate is .111–.244, and limits shorter than the official ones may depress success.
  • The probe reads only the first token, with just two manipulations. Cell 4 comes from only 9 problems. Fidelity of P(Reach) is unverified.
  • Environment. T=1 with no top-p is not the official evaluation. Timeout rates may be affected by load; the runs span three sessions with pauses and interruptions (§8).
  • Problem selection. Problems were selected from calibration by outcome mix, so regression to the mean is possible. Three of B's prefixes already have success 0 under normal.
  • No training. All conclusions concern inference with trained weights and say nothing about RL updates.

8. Deviations

Relative to PREREG.md. The three items in its §7 (length limits, sizes, 8-bit reference) are already recorded there.

  1. The placebo correlation cannot be computed. My design has only one placebo state per problem, so no within-problem correlation exists, and the placebo columns in A_posttool_vs_placebo.csv are empty. A post-hoc fixed-effects interaction replaces it.
  2. pass@8 became pass@6, since each state has only 6 continuations.
  3. answer_div is almost always 1, so its statistics are degenerate (p=1.0) and should not be interpreted.
  4. Post-hoc analyses: void split (give-up / other), fixed-effects slopes, split by source, branch positions, give-up probe. All were added after seeing the data and are labelled.
  5. Fidelity: the first check had only 1 post-tool first token; a post-tool replay and a 4-bit self-control were added post hoc. The reference is 8-bit, not fp16.
  6. Analysis corrections: (a) last turns cut by the budget are no longer void; (b) first turn had included 48 A placebo turn-0 rollouts and C mid-turn branches, and after correction first-turn H10 moves from .171 to .176 and post-tool from .690 to .685, with Figure 1 regenerated; (c) the case-study script picked the same rollout twice when success was 0, now fixed. Interim numbers given earlier in chat are superseded by this report.
  7. Probe code change: cell 3 thrashed memory, so the code was changed to share the prefix. Cells 1–2 use the old path, cells 3–4 the new one.
  8. Run history: three sessions. I ran the probe concurrently with B, and B added no rollouts 10:05–11:16. The end of a Claude Code session interrupted the job once (B=325); two low-battery pauses followed (12:04–14:09; from 15:25 until stopped by the user, resumed 18:37 with B=390). Rollouts not yet written at an interruption were rerun. The deadlines for B and C moved from 15:30 / 17:00 to 22:00 / 22:45, and neither was actually cut off (stop=None). Pauses and machine load may have affected tool timeout rates.
  9. ARPO replication (pre-registered as time permitting) was not run.

9. Suggested items for the 6 November discussion

Most worth discussing (observed results):

  1. The dissociation in B: form can raise entropy without hurting quality, and content can hurt quality while the entropy change goes undetected. This poses a concrete question for approaches such as ARPO, AEPO and TAO-RL that treat high post-tool entropy as an exploration signal.
  2. The fixed void string and its one-token trigger: this may affect how void-turn statistics and filtering are understood. Ask for a judgement on whether this is peculiar to one model or a general issue worth checking.

Decisions that need the professor's judgement:

  • How these results relate to the survey: whether they merit a small empirical section in the survey, or should only be recorded as a later direction. The survey remains the first direction of the project (plan.md §1), and this does not change it.
  • If this continues, whether the next step needs a GPU: fp16 weights, 50 or more prefixes, and the ARPO model.
  • If this continues, where the question should sit: whether a "form versus content decomposition" is enough of a research question, or whether it should go on to training (for example, changing only the form of feedback and seeing whether an entropy bonus is drawn to it).

What should not be claimed yet:

  • That entropy guidance is useless (C has only 10 problems).
  • That this contradicts ProCredit.
  • Anything about whether void is related to gradient explosion.
  • That the source of the Reach string is known.

Follow-up Analysis Needed: check whether the string appears in SimpleTIR's training environment; run the same probe on other checkpoints; retest B's H_first and H10 on fp16; add samples per condition to settle the success effects of irrelevant and empty; control the tool-call budget in C and add problems.
